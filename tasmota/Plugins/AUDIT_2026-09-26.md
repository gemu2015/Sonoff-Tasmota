# BinPlugin audit, 2026-09-26 (ESP32 / Tensilica)

Tool: `tasmota/Plugins/blib_audit.py` — `--elf` (default: the plugin-host `firmware.elf`
of the last `build_plugin.py` run) or `--bin FILE` (an extracted `*_32.bin`, e.g. a shipped
one). The `--bin` mode was calibrated against the ELF mode: identical results on HTU21 and
I2SAUDIO; on the large MATTERF it misses ~10 % (under-reports, never over-reported).

Categories that are **certain** crashes/wrong values once the module is relocated:

| class | meaning |
|---|---|
| LIT-OUT | `l32r` reads a literal slot OUTSIDE the module — the linker merged an identical constant with one in the host (see below) |
| PTR-FW / PTR-ABS | literal holds an absolute address in the host (`.rodata` string/table, host function) |
| PTR-BSS | literal holds the address of a host global (`.bss`) |
| ROM | literal holds a ROM address (double/libgcc helpers) — the plugin build links the classic-ESP32 ROM, wrong on S2/S3 |
| CALL-OUT | direct `call` to code outside the module |

## Proof on the device (.39, ESP32-S3, 2026-09-26)
Same device, same call `blibtest mb_crc16 313233343536373839` ("123456789", Modbus CRC must be 0x4B37):

| CRC_BLIB | audit | mb_crc16 | crc32 / crc8 (not flagged) |
|---|---|---|---|
| rebuilt from today's tree — LIT-OUT: the start value 0xFFFF read from a host slot | 1 problem | **0xB7C1 — wrong** | 0xCBF43926 / 0xA1 — correct |
| shipped build (May 9) | clean | **0x4B37 — correct** | correct |

The audit's prediction holds in both directions: a LIT-OUT finding is a real wrong value on
the device, not a theoretical one.

Second device test, same day — BMP280 on .39 (ESP32-S3), one sensor, two plugins:

| plugin | audit | result on .39 |
|---|---|---|
| BMXx80_32.bin (May 12) | clean | 22.6 °C, 1010.4 hPa — works |
| BMP_32.bin (May 17) | 5 LIT-OUT, 6 PTR-ABS, **1 ROM** | **crash right after `iniz`** (Exception, EPC 0x40056f60 in S3 ROM) |

The ROM finding is `__divdi3` (64-bit division in the pressure compensation) called at its
**classic-ESP32** ROM address 0x4000ca84 — on the S3 that address is inside unrelated ROM code
(Uart_Init_USB area). The plugin-host env links against the classic ESP32 ROM, so any ROM call
works on an ESP32 and fails on S2/S3. This is why such a plugin can have "always worked":
on the chip it was used on, the address was right.

## Main cause: literal merging by the Xtensa linker
The plugin block sits at the END of `.flash.text` (`patch_linker_file.py`). Linker relaxation
merges identical 32-bit literals within `l32r` reach (256 KB backwards), so a plugin's
`0`, `0xFFFF`, `100000`, `0x10624DD3` (÷1000) or the address of `memcpy` gets read from a
slot inside some host/WiFi-blob function — which does not exist once the module is extracted.
`-Wl,--no-relax` is not an option (IDF exception vectors need relaxation).

Experiment (reverted): moving the plugin block to the START of `.flash.text` removed every
LIT-OUT of HTU21 (5 → 0) — but the linker then moved ~11.6 KB of ordinary host literals
(`.literal._Z14IndexSeparatorv`, `tmod_float*` …) INTO the plugin literal area
(`.plugin.mod_part.literal`), bloating the module 1.8 → 13.4 KB. A clean fix is probably a
dedicated output section for the plugin block (nothing foreign can be merged in or out) —
a change to the framework `sections.ld`, not done yet.

Causes per plugin: TCS34725 — `__divsf3`, `pow`, ROM double math, `TwoWire::begin` and the
`Wire` object used directly; SML — 9× `memcpy` + `memset` via merged literals, ÷100 constant,

## Fixed (2026-09-26, evening)

**TCS34725** — 49 → 1 certain problem (shipped May build: 37).
- `getData()`: all float divisions via `fdiv` (jumptable); the DN40 constants were `double`
  literals (soft-double at ROM addresses) and are now a PROGMEM `float` table read via
  `FLTC()`; `atime_ms` and the settle delay in integer arithmetic (`x*1229>>9` ==
  ⌊x·2.4⌋ for x = 0..256 — a `/10` would bring back the literal `0x66666667`).
- The Adafruit driver's `getRGB` / `calculateColorTemperature(_dn40)` / `calculateLux`
  (unused by xsns_124; `pow`, `__divsf3`, double) are native only; `powf` stays in plugin
  mode but outside the module, otherwise lib_div/Adafruit_TCS34725 gets pulled into the
  plugin-host link for other drivers' `powf` calls (duplicate symbols).
- Bus pointer: `_DUAL_WIRE_FOR()` took `&Wire`/`&Wire1` of the plugin-host firmware
  (PTR-BSS) — in plugin mode it now reads `jt[0]`/`jt[1]`; `init()` no longer calls the
  non-virtual `TwoWire::begin` (the host has set the bus up).
- Native: `SETMINREGS` was never defined outside plugin mode (the native TCS build could not
  compile); now an empty macro next to `SETREGS`.
- Left: one LIT-OUT `0x0000FFFF` (saturation 65535) — merged literal, for the linker fix.

**BMP** — `BMP_32.bin` retired to `build_output/firmware/Plugins/ESP32/TENSILICA_ausgemustert/`.
Regenerated with today's scaffolder it still has 13 certain problems (`__divdi3`, `__divsf3`,
host `HTTP_SNS_*` strings, merged ROM-address literals). BMXx80 covers the same four chips.
- `scaffold.py` flags `NEEDS-INT64DIV` (64-bit `/`/`%` has no jumptable route).
- `build_plugin.py` runs `blib_audit.py` after every Tensilica build and reports
  `!! AUDIT: n certain problem(s)` in the summary.
