### Changes in v1.3.11 (2026-04-22):
- **Variadic `addLog` / `addLogLevel`** — printf-style debug logging directly from `.tc` source. Compiler desugars `addLog("x=%d t=%.1f s=%s", x, t, name)` into a chain of single-value `sprintf` syscalls writing into a shared 160-byte heap scratch, then a single `LOG`/`LOG_LEVEL` syscall. Format string must be a literal; specifiers `%d %i %u %x %X %c %f %e %g %s` plus width/precision (`%.1f`, `%5d`, …). Trailing literal text after the last specifier is appended as a separate const-cat. Existing `addLog("literal")` and `addLog(charBuf)` paths are unchanged. Scratch buffer is allocated **only when the variadic form is used** — programs that don't use it pay zero heap. Output is still truncated to ~128 chars on device (Tasmota's `LOGSZ`). Pure compile-time desugar, no VM/firmware change.
- **Upload allocator honors `?fsz=N`** — `tc_upload` now sizes its receive buffer to the actual program length (rounded up by 16 bytes), instead of always grabbing the full `TC_MAX_PROGRAM` (64 KB). Long-running devices with fragmented heap that no longer have a contiguous 64 KB block can now upload small programs (most are <8 KB). All clients updated to send the hint: `tc_deploy.mjs` and both upload paths in the IDE's `index.html`. Devices on older clients still work — the parameter is optional and the firmware falls back to 64 KB if unset.
- **IDE: SML descriptor placeholder regex** — the meter-template substitution now matches `%rxpin%` and `%0rxpin%` interchangeably (leading `0` optional), same for `%txpin%` and `%smlf%`. Empty filter field no longer wipes `%smlf%` to an empty string. Fixes copy-paste from sample descriptors that use either form.
- **Compiler refactor**: variadic-format expansion extracted into `emitSprintfChain(emitDst, fmt, valArgs, isAppend, name, line)` so `sprintf`/`sprintfAppend` and the new `addLog`/`addLogLevel` paths share one loop. No semantic change for existing `sprintf` calls.
- **Release tooling**: new `release.sh` script — one command builds the 4 standard binaries, bundles the IDE, prepends a new "Changes in vX.Y.Z" section to the existing release notes, and uploads everything to the GitHub `testing` pre-release. Supports `--dry-run`, `--skip-build`, `--skip-upload`, `--notes <file>`. Auto-extracts the version from `src/opcodes.js`.
